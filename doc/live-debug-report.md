# 微信朋友圈实机调试记录

调试日期：2026-10-11，时区 Asia/Shanghai。
环境：Windows、微信 4.1.13.65、深色主题、125% DPI；客户区 1045 × 809。

## 任务拆分

1. 导航：识别发现入口，点击朋友圈菜单，验证绿色选中状态。
2. 截图及识别：裁出右侧列表，识别“··”边界、昵称和图片候选。
3. 媒体：点击缩略图，验证放大图片，右键识别“另存为”，保存并返回列表。
4. 连续采集：单次滚动，等待稳定，验证重叠，拼接分段并复用已保存的媒体。
5. 回归：保留动作证据、异常日志和停止原因，补充自动测试。

## 实际发现与修复

| 问题 | 修复 |
| --- | --- |
| 发现图标通知红点破坏模板匹配 | 模板只保留图标中心，页面模板仍统一由 UiProfile 维护 |
| 鼠标悬停样式和指针效果进入截图 | 截图前把指针移到客户区左下角 |
| 整窗含固定侧栏，无法稳定拼接 | UiProfile 维护参考 DPI 和列表边距，按实际 DPI 裁出列表 |
| 首屏封面没有动态边界，过早停止 | 已验证朋友圈选中时，允许在最大帧数限制内继续寻找首条边界 |
| 封面把昵称推到原来的识别范围之外 | 首条片段扩大昵称搜索范围，仍核对蓝色文字和邻近头像 |
| 封面颜色被当作背景，遗漏图片 | 从整个卡片的主色桶估计背景，过滤宽幅封面 |
| 图片在主窗口内放大，窗口句柄不变 | 支持 auto/embedded/independent；内嵌模式用 Airtest 验证原缩略图被放大 |
| 横图匹配范围过窄，细密树叶缩放匹配失真 | 扩大查看器搜索范围，保留原截图像素，并使用更细的多尺度步长；阈值保持 0.9 |
| Win32 子控件查询未按 class_name 过滤，搜索框及工具栏混入候选 | 显式核对 Edit 类与文件名控件 ID 1001 |
| 刚检测到滚动画面变化时动画尚未结束 | 验证区域变化后继续只读截图，等连续两帧像素一致再返回最终坐标 |
| 长时间保存媒体后，视口底部图片加载使原底部条带失配 | 用中部和底部两个条带验证移动量，阈值保持 0.95，歧义或移动量冲突立即停止 |
| 125% DPI 滚动让两个条带的整数定位相差 1 像素 | 允许 1 像素舍入误差，使用置信度更高的移动量；更大冲突仍停止 |
| 缩略图哈希因子像素渲染改变而重复下载 | 缓存同时核对列表流位置、横向位置、尺寸和 Airtest 彩色图像匹配；仅复用同一次连续采集的已保存文件 |

内容连续性统一由 validation.region_unchanged 校验。点击、滚动和 Escape 均只执行一次，
失败不会自动重发输入；ActionResult 保存 attempted、executed、前后截图和验证结果。

## 输出及复现

最终结果按独立运行统计：

| 阶段 | 实机结果 | 证据 |
| --- | --- | --- |
| 连续截图与昵称识别 | 8 帧、7 次滚动、3 个分段，达到 max_screens 正常停止；一个分段识别到昵称 | `data/live-debug/continuous/feed_a9a1c205-a58c-4727-9532-87041a82bcec/manifest.json` |
| 图片保存、缓存及继续滚动 | 2 帧、1 次滚动、2 个分段，达到 max_screens 正常停止；两份卡片均 captured，4 条媒体引用复用 2 个实际文件 | `data/live-debug/integrated/feed_c5dd380f-d679-4ace-b827-d2ae23a4c142/manifest.json` |
| 原文件验证 | 实际另存为两张 JPEG，尺寸 1440 × 1920 和 1080 × 1920；可解码，两个不同 SHA-256 | `data/live-debug/integrated/cards_a10a6b6d-e42e-4dc6-9bdf-0eb685ab997e/media/` |
| 自动回归 | Ruff check、格式检查及差异空白检查通过；179 项 unittest 通过 | `data/test-results.txt` |

媒体缓存使用原像素和两像素搜索边距校准同位置预览，彩色匹配阈值保持 0.97。
Airtest 只寻找这个几何位置内的最佳候选，避免在极小搜索区域进行多目标扫描。
缓存不跨运行复用；调试期间不同运行产生的重复文件保留供追溯。

实机调试文件位于 `data/live-debug/`，日志位于 `logs/live-debug.log`，均为本地调试产物。
失败尝试也保留证据，不应把目录中所有图片计为一次成功运行。
`feed_<UUID>/manifest.json` 记录帧、分段、昵称及停止原因；
`cards_<UUID>/card_*.json` 关联卡片与媒体；`media/asset_*` 是查看器实际另存为的文件。

常规运行：

```powershell
uv run wemo2 --config wemo2.moments.toml
```

VS Code 选择 `wemo2.collectors: 调试朋友圈路由` 后按 F5，使用同一朋友圈配置。
默认最多 20 帧；通过配置文件调整 max_screens，不增加业务 CLI 选项。

## 验证边界

- 本轮实机环境为深色主题和 125% DPI。浅色主题、其他微信布局和 Android 尚未实机验证。
- 昵称为 OCR 原文，表情及表情附近的分段文字可能遗漏；不能用作稳定作者 ID。
- 保存的是微信查看器提供的文件；没有对比发送者源文件，不能宣称最高分辨率原图。
- 本轮实际验证图片，视频播放、保存和动态画面的稳定判断仍需单独验证。
- 视觉采集输出本地截图与结构化证据，尚未转换为 Observation 或接入 Memos。
- max_screens 是调试上限，no_progress 是没有观察到进展，都不能证明已备份全部历史。
